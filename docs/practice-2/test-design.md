# Test-design ядра: Authorization и Card-Management

## 1. Классы эквивалентности

| Поле / Параметр | Классы | Представитель | Ожидаемый результат |
|---|---|---|---|
| `card_status` (статус карты) | Валидный: ACTIVE<br>Невалидные: INACTIVE, BLOCKED, EXPIRED, нет в базе | ACTIVE<br>INACTIVE<br>BLOCKED<br>EXPIRED<br>несуществующий PAN | Операция успешна (код 00)<br>Отказ CARD_INACTIVE<br>Отказ CARD_BLOCKED<br>Отказ (код 54)<br>Отказ (код 14) |
| `expiryDate` (срок действия) | Валидный: текущий месяц или будущее<br>Невалидный: срок истек (прошлый месяц) | 0926, 1227<br>0826 | Операция успешна (код 00)<br>Отказ (код 54) |
| `dailyLimit` (дневной лимит) | Валидный: сумма <= остатка лимита<br>Невалидный: сумма > остатка лимита | 500.00 руб (при лимите 1500)<br>2000.00 руб (при лимите 1500) | Операция успешна (код 00)<br>Отказ (код 61) |
| `monthlyLimit` (месячный лимит) | Валидный: сумма <= остатка лимита<br>Невалидный: сумма > остатка лимита | 1000.00 руб (остаток 3000)<br>5000.00 руб (остаток 3000) | Операция успешна (код 00)<br>Отказ (код 61) |

| Доступность CMS | Валидный: CMS доступен<br>Невалидный: таймаут / CMS отключен | CMS отвечает<br>CMS выключен | Операция успешна (код 00)<br>Отказ (код 05, ISSUER_TIMEOUT) |
| Длина PAN (CMS) | Валидный: 16 цифр с верным Луном<br>Невалидные: меньше 16, больше 16 | 16 цифр<br>15 цифр, 17 цифр | Карта создана (HTTP 200/201)<br>Ошибка валидации (HTTP 400) |

## 3. Попарное тестирование (pairwise)
- **Модель pict**: файл `docs/practice-2/pict/model.txt` (7 параметров, 2 ограничения).
- **Сгенерированный набор**: файл `docs/practice-2/pict/cases.txt`.
- **Обоснование 2-wise покрытия**:
   - Полный перебор потребовал бы очень много тестов. Попарное покрытие сокращает набор при сохранении проверки всех парных связок.
- **Критичные сочетания, добавленные вручную**:
   - Полное исчерпание всего: сумма операции равна дневному лимиту, месячному лимиту и остатку баланса одновременно. Проверяет списание баланса в ноль и исчерпание лимитов без ошибок округления.
   - Повторный вызов авторизации с тем же RRN (проверка идемпотентности, чтобы сумма не списалась второй раз).
